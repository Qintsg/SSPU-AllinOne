# Feature Specification: 本地个人数据 MCP 服务

**Feature Branch**: `feature/frontend-visual-refresh`

**Created**: 2026-09-10

**Status**: Implemented (桌面版；跨设备与第二客户端验收待完成)

**Input**: User description: "对于允许的客户端开启 HTTP 形式的 MCP 服务器，开放在运行设备端口上，供其它应用尤其是 Agent 按授权访问个人数据并进行个性化问答；可设置仅本机或局域网访问，并可选择启用 API Key。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 安全开启本地 MCP 服务 (Priority: P1)

用户可以在受支持设备上显式开启 MCP 服务，看到实际访问地址、运行状态和停止入口，并可随时关闭服务。

**Why this priority**: 服务生命周期是其它应用访问数据的前提，错误地默认开启或无法停止会直接形成隐私风险。

**Independent Test**: 在默认配置下启动应用，确认服务保持关闭；用户完成配置并开启后，受支持的 MCP 客户端能够连接，关闭后已有和新请求均停止。

**Acceptance Scenarios**:

1. **Given** 用户从未配置 MCP 服务，**When** 应用启动，**Then** 不监听任何 MCP 端口且设置页明确显示“未开启”。
2. **Given** 用户选择合法端口并显式开启，**When** 服务启动成功，**Then** 设置页显示运行中、实际访问地址、访问范围和停止操作。
3. **Given** 服务正在运行，**When** 用户关闭服务、退出应用或应用进入隐私锁定状态，**Then** 服务停止接受请求且不残留可访问端口。
4. **Given** 端口已被占用或平台不支持，**When** 用户尝试开启，**Then** 应用保持关闭并给出可执行的恢复建议。

---

### User Story 2 - 按数据范围授权外部 Agent (Priority: P1)

用户可以逐类决定外部客户端能读取哪些个人数据，使 Agent 只获得完成个性化问答所需的最小信息。

**Why this priority**: 个人数据访问必须可见、可控且默认拒绝，不能把“连接成功”等同于“获得全部数据”。

**Independent Test**: 只授权一个数据类别后连接客户端，验证其只能发现和读取该类别的工具或资源，未授权类别、凭据和身份材料始终不可见。

**Acceptance Scenarios**:

1. **Given** 服务已开启但所有数据范围均未授权，**When** 客户端列出或调用能力，**Then** 不返回任何个人数据能力。
2. **Given** 用户仅授权课程与考试，**When** 客户端请求日程和校园卡数据，**Then** 日程请求返回最小必要字段，校园卡请求被明确拒绝。
3. **Given** 用户撤销某项授权，**When** 客户端随后再次请求该项数据，**Then** 新请求立即被拒绝，无需重启服务。
4. **Given** 已授权数据当前没有本地快照或已过期，**When** 客户端读取，**Then** 返回无数据或陈旧状态及时间戳，不静默联网刷新也不编造结果。

---

### User Story 3 - 选择本机或局域网访问 (Priority: P1)

用户可以选择只允许同一设备上的应用访问，或显式允许同一局域网中的其它设备访问。

**Why this priority**: 网络绑定范围决定暴露面，局域网访问必须是清晰、可逆的高风险选择。

**Independent Test**: 分别以“仅本机”和“局域网”模式启动服务，从本机与同网段另一设备验证可达性、提示和认证要求。

**Acceptance Scenarios**:

1. **Given** 访问范围为“仅本机”，**When** 同网段其它设备尝试连接，**Then** 无法访问服务。
2. **Given** 用户切换到“局域网”，**When** 阅读并确认风险提示且认证配置有效，**Then** 服务监听所有可用网络接口并显示可供其它设备使用的实际局域网地址。
3. **Given** 局域网模式正在运行，**When** 用户切回“仅本机”，**Then** 外部设备连接立即失效且本机端点继续按新配置工作。

---

### User Story 4 - 配置可选 API Key (Priority: P1)

用户可以生成、复制、轮换或关闭 API Key；本机模式可按需关闭认证，局域网模式始终要求认证。

**Why this priority**: API Key 是阻止同设备或同网段无关应用读取个人数据的基本边界，但本机开发场景仍需要可控的低摩擦模式。

**Independent Test**: 在本机模式分别验证启用与关闭 API Key；在局域网模式验证无 Key、错误 Key、旧 Key和新 Key的结果。

**Acceptance Scenarios**:

1. **Given** 本机模式且 API Key 已开启，**When** 客户端未携带或携带错误 Key，**Then** 请求在读取任何个人数据前被拒绝。
2. **Given** 本机模式，**When** 用户关闭 API Key，**Then** 应用明确提示同设备其它进程可能访问，并允许用户再次开启认证。
3. **Given** 用户选择局域网模式，**When** API Key 尚未开启，**Then** 应用要求先生成 Key，不能以无认证状态启动。
4. **Given** 用户轮换 API Key，**When** 客户端继续使用旧 Key，**Then** 旧 Key立即失效，新 Key可正常访问已授权范围。

---

### User Story 5 - 查看访问记录并快速撤销 (Priority: P2)

用户可以查看最近的访问时间、来源、请求能力和结果状态，在发现异常时立即停止服务、轮换 Key或撤销数据授权。

**Why this priority**: 可审计与快速撤销能让用户判断谁访问过哪些类别，同时避免审计本身复制敏感内容。

**Independent Test**: 使用成功、认证失败、越权和无数据请求生成访问记录，验证记录可理解、不包含 Key、请求参数或个人数据正文，并可从记录页直接进入处置操作。

**Acceptance Scenarios**:

1. **Given** 客户端完成一次请求，**When** 用户查看访问记录，**Then** 可以看到时间、来源地址、能力名称、允许或拒绝状态和耗时。
2. **Given** 请求携带敏感参数或返回个人数据，**When** 审计记录写入，**Then** 不保存 API Key、完整参数、响应正文或凭据。
3. **Given** 用户发现异常来源，**When** 点击停止服务、撤销授权或轮换 Key，**Then** 后续访问立即遵守新状态。

### Edge Cases

- 用户配置了保留端口、越界端口或已被占用端口时，服务不得部分启动或悄悄改用未知端口。
- 设备网络接口、IP 地址或 Wi-Fi 在运行中变化时，页面必须刷新实际地址；旧接口不得继续意外暴露。
- 请求携带伪造主机、来源或不匹配的协议元数据时，必须在进入个人数据能力前拒绝。
- 多个客户端同时请求、重复请求或在授权切换瞬间请求时，每个请求都必须使用执行时的最新授权快照。
- 客户端请求过大的结果集时，必须分页或截断并明确告知，不得一次导出全部历史数据。
- 数据模块被用户设置为“停止获取”时，MCP 只能读取已有本地快照，不得绕过设置联网。
- 应用切换账号、清除数据或启用隐私锁时，旧账号数据不得通过仍在执行的请求返回。
- 局域网模式使用未加密 HTTP 时，必须明确提示只适用于可信网络；不得把 API Key 描述为传输加密。
- 操作系统防火墙或移动平台生命周期阻止监听时，必须显示平台限制，不能虚报服务正在运行。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 默认关闭 MCP 服务，且仅在用户显式开启后监听端口。
- **FR-002**: 系统 MUST 仅在平台与当前应用生命周期支持安全监听时提供开启能力；不支持时 MUST 显示明确原因。
- **FR-003**: 系统 MUST 提供符合当前稳定 MCP 规范的 HTTP 端点，并向兼容客户端提供能力发现与只读调用。
- **FR-004**: 系统 MUST 允许用户配置合法端口，并在启动前检测端口占用、绑定失败和平台权限失败。
- **FR-005**: 系统 MUST 提供“仅本机”和“局域网”两种访问范围；默认 MUST 为仅本机。
- **FR-006**: 系统 MUST 将“仅本机”限制在回环接口；“局域网”可监听所有接口，但 MUST 经过单独风险确认并展示实际可访问地址。
- **FR-007**: 系统 MUST 对请求的主机与来源信息进行校验，防止网页或伪造来源绕过网络范围限制。
- **FR-008**: 系统 MUST 提供 API Key 的生成、一次性复制或受保护显示、轮换和关闭能力；API Key 默认开启并保存在系统安全存储中。
- **FR-009**: 系统 MUST 允许仅本机模式关闭 API Key，但 MUST 显示风险；局域网模式 MUST 强制启用 API Key。
- **FR-010**: 系统 MUST 在认证失败时先拒绝请求，不得读取、缓存或返回任何个人数据。
- **FR-011**: 系统 MUST 默认不授权任何个人数据，并允许用户按数据域或具体能力独立授权与撤销。
- **FR-012**: 系统 MUST 至少规划个人资料、课程与考试、成绩与培养计划、校园活动、校园卡、消息、学校邮箱和应用偏好等只读数据域，并允许分阶段交付。
- **FR-013**: 系统 MUST 永不暴露密码、Cookie、Token、API Key、安全存储原文、会话材料、完整本地文件路径或其它认证秘密。
- **FR-014**: 系统 MUST 仅返回完成查询所需的最小字段，并对列表设置范围、分页和单次返回数量上限。
- **FR-015**: 系统 MUST 默认只读取本机已有快照，返回数据时间与陈旧状态；不得因 MCP 调用绕过模块获取设置或自动访问校园服务。
- **FR-016**: 系统 MUST 只提供读取和查询能力，不提供选课、预约、支付、充值、发信、标记已读、修改设置或其它写操作。
- **FR-017**: 系统 MUST 在授权、账号、隐私锁或服务配置变化后立即应用新边界，并阻止旧请求返回已撤销的数据。
- **FR-018**: 系统 MUST 在用户关闭服务、退出应用或进入隐私锁定状态时停止接受请求并释放监听端口。
- **FR-019**: 系统 MUST 显示服务的启动中、运行中、停止中、已停止和失败状态，以及端点、范围、认证状态和最近访问时间。
- **FR-020**: 系统 MUST 记录脱敏访问审计，至少包含时间、来源地址、能力名称、允许或拒绝状态和耗时，且不得记录请求参数、响应正文或秘密。
- **FR-021**: 系统 MUST 提供速率限制、并发限制、请求体大小限制、调用超时和结果上限，并对超限请求返回可理解的错误。
- **FR-022**: 系统 MUST 让用户能够从设置页立即停止服务、撤销数据授权、清除审计记录和轮换 API Key。
- **FR-023**: 系统 MUST 在局域网未加密 HTTP 模式下明确说明流量和 API Key不具备传输加密，并建议仅在可信网络使用。
- **FR-024**: 系统 MUST 保持服务配置和授权选择持久化，但 API Key与其它秘密不得进入普通状态文件、日志、崩溃报告或导出数据。

### Key Entities

- **MCP 服务配置**: 表示是否启用、访问范围、端口、API Key策略、自动启动偏好和风险确认状态。
- **数据授权**: 表示某个个人数据域或具体只读能力是否允许外部客户端访问，以及最近修改时间。
- **个人数据能力**: 对外可发现的只读工具或资源，包含稳定名称、用途、所属数据域、输入范围和最小输出字段。
- **API Key凭据**: 用于验证客户端请求的秘密及其版本状态，仅允许生成、验证、轮换和删除。
- **服务运行状态**: 表示启动、运行、停止或失败状态，包含实际绑定地址、端口、可访问地址和最近错误摘要。
- **访问审计记录**: 脱敏记录一次能力请求的时间、来源、能力、授权结果、完成状态和耗时。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新安装和升级后的应用在 100 次启动检查中均不会未经用户操作监听 MCP 端口。
- **SC-002**: 用户能够在 2 分钟内完成服务开启、复制连接信息并让一个兼容客户端列出已授权能力。
- **SC-003**: 仅本机模式下，来自其它设备的 100% 连接尝试均无法访问服务；局域网模式下，未认证或错误认证请求的拒绝率为 100%。
- **SC-004**: 对所有未授权数据域、已撤销授权和禁用模块的测试请求，越权数据返回数量为 0。
- **SC-005**: 自动化敏感信息扫描确认 API Key、密码、Cookie、Token、安全存储原文和个人数据正文进入日志或审计记录的数量为 0。
- **SC-006**: 在已有本地快照且返回不超过 100 条记录时，95% 的只读查询在 500 毫秒内返回首个结果。
- **SC-007**: 服务关闭、隐私锁定、授权撤销或 API Key轮换后，新的访问边界在 1 秒内生效。
- **SC-008**: 端口冲突、认证失败、越权、超限、无数据和陈旧数据场景均有可区分的结果，测试覆盖率达到 100%。
- **SC-009**: 使用至少两个独立 MCP 客户端完成能力发现与只读调用，结果字段、分页和错误行为一致。
- **SC-010**: 在每个声明支持的平台上完成本机模式验收；声明支持局域网的平台还必须从同网段另一设备完成认证访问与撤销验证。

## Assumptions

- 首版服务端支持范围为 Windows、macOS 和 Linux；Android、iOS 受后台生命周期和服务端 SDK 支持限制，首版只显示不支持说明，后续另行评估前台限定模式。
- 首版使用当前稳定 MCP 规范，不为旧版 HTTP+SSE 客户端维护第二套端点；确有兼容需求时另行评估。
- MCP 调用只读取现有本地快照，不触发远端刷新；数据新鲜度由结果元数据明确表达。
- API Key默认开启；为了满足本机开发和受控集成，仅回环模式允许用户显式关闭。
- 局域网模式的 `0.0.0.0` 是监听地址，不是客户端连接地址；应用会展示设备实际局域网 IP。
- 首版不提供 TLS 证书管理；局域网 HTTP 仅面向可信网络，公网、端口转发和互联网暴露均不在范围内。
- 审计记录默认仅保留最近 200 条，用户可随时清除；记录不包含参数和结果正文。
