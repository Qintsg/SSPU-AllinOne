# Feature Specification: 校园工作台响应式收敛

**Feature Branch**: `bugfix/responsive-ui-convergence`

**Created**: 2026-09-11

**Status**: Draft

**Input**: User description: "收敛教务、课表、信息、邮箱、快速跳转、AI 服务与桌面导航的布局和交互问题，并参考附件与 Cockpit Tools 的高密度控制台风格。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在任意常用窗口中无障碍浏览校园数据 (Priority: P1)

学生在手机、平板和桌面窗口打开教务、课表、信息、邮箱等页面时，关键数据应在当前页面范围内清晰排布，并可通过页面内滚动查看完整内容，不出现溢出、遮挡或大片无意义空白。

**Why this priority**: 当前布局溢出会直接阻止用户查看内容，是所有后续体验优化的前提。

**Independent Test**: 分别在 360×800、768×900、1200×900 窗口打开所有受影响页面，检查内容可达、滚动有效且无渲染溢出。

**Acceptance Scenarios**:

1. **Given** 用户使用窄屏窗口，**When** 打开任一受影响页面，**Then** 卡片与操作控件会重排或换行且不发生横向或纵向溢出。
2. **Given** 邮件或信息内容超过可视区域，**When** 用户滚动对应内容区，**Then** 可查看完整内容而不会把整个页面无限拉长。
3. **Given** 用户打开周课表，**When** 课程跨多个节次，**Then** 课程块按星期和节次占据正确跨度且页面可滚动。

---

### User Story 2 - 快速获得准确、精简的教务概览 (Priority: P1)

学生进入教务页后，可以在一个紧凑的头部区域看到姓名、学号、院系、专业、班级和可靠的学分指标，并清楚看到下一场考试，而不被重复卡片和低价值说明干扰。

**Why this priority**: 已获学分错误为零会误导用户，重复卡片也降低了核心信息可读性。

**Independent Test**: 使用包含已通过课程和下一场考试的样例数据渲染教务页，核对字段、学分与卡片集合。

**Acceptance Scenarios**:

1. **Given** 成绩记录中存在已通过课程，**When** 打开教务概览，**Then** 已获学分等于所有已通过成绩学分之和而不是固定为零。
2. **Given** 用户查看教务页，**When** 页面加载完成，**Then** 完成度、学习档案、详细来源按钮和冗余档案字段均不再出现。
3. **Given** 下一场考试信息存在，**When** 宽度变化，**Then** 考试卡与相邻概览区域对齐并保持内容完整。

---

### User Story 3 - 集中刷新并筛选可信信息来源 (Priority: P2)

学生只需区分官网与微信公众号/服务号两个来源类别，并可从右上角一次刷新所有已启用渠道；分页和来源面板在不同宽度下仍然易用。

**Why this priority**: 来源分类与刷新语义不一致会造成用户误解，也增加重复操作。

**Independent Test**: 启用两个来源，触发一次刷新并检查两个来源均被调度；随后切换来源和分页，验证内容与滚动位置。

**Acceptance Scenarios**:

1. **Given** 官网和微信渠道均启用，**When** 用户点击右上角刷新，**Then** 两类启用渠道都被刷新。
2. **Given** 用户查看来源筛选，**When** 页面加载，**Then** 只显示“全部”“官网”“微信公众号/服务号”，教务处内容归入官网。
3. **Given** 用户跳转到另一页，**When** 页码切换完成，**Then** 信息列表回到顶部且分页控件在当前宽度内完整显示。

---

### User Story 4 - 在屏幕内高效阅读邮件 (Priority: P2)

学生在桌面端通过列表与详情双栏阅读邮件，在移动端进入独立详情；列表只显示时间、标题和发件人，正文仅呈现本机解析的安全文本，不加载远端内容。

**Why this priority**: 当前邮件列表与详情随内容无限增高，阅读效率低且远端内容存在隐私风险。

**Independent Test**: 加载长邮件列表与长正文，在桌面及移动窗口中验证独立滚动、字段精简与远端内容关闭。

**Acceptance Scenarios**:

1. **Given** 邮件数量超过一屏，**When** 用户滚动列表，**Then** 列表卡保持在可视区域并仅显示时间、标题和发件人。
2. **Given** 一封邮件正文很长，**When** 用户打开详情，**Then** 详情在自己的可滚动区域内排版展示，并且不请求远端图片、脚本或样式。
3. **Given** 用户进入邮箱，**When** 页面加载，**Then** 搜索框和旧的本机读取/桌面布局说明不再出现。

---

### User Story 5 - 使用高密度工作台完成快捷操作 (Priority: P3)

学生可以通过横向换行的快速跳转卡片、紧凑的 AI 服务配置和固定在左下角的设置入口完成操作，减少空白和视线移动。

**Why this priority**: 这些调整统一产品信息密度与导航习惯，提升日常操作效率。

**Independent Test**: 在桌面和窄屏窗口检查快速链接换行、AI 卡片双栏/单栏切换、端口操作与设置入口位置。

**Acceptance Scenarios**:

1. **Given** 快速链接数量较多，**When** 页面宽度允许，**Then** 链接横向排列并自动换行，不形成单列长卡片。
2. **Given** 用户在桌面宽屏打开 AI 服务，**When** 查看访问配置，**Then** API Key/访问记录与外部应用授权以窄宽双栏等高展示；窄屏时自然改为单栏。
3. **Given** 用户准备开启 MCP 服务，**When** 编辑端口，**Then** 服务开关位于端口输入栏右侧。
4. **Given** 用户使用桌面侧栏，**When** 寻找设置，**Then** 设置入口固定在侧栏最左下方且其他目的地索引行为不变。

### Edge Cases

- 个人资料、下一场考试、体育考勤或成绩数据缺失时，页面应显示清晰空态而不是零值误导或布局坍塌。
- 邮件标题、发件人或正文为超长连续文本时，内容应换行或截断且保持滚动可达。
- 课表存在同一天重叠课程、跨多个节次课程或无课程时，网格应保持星期与时间轴对齐。
- 仅启用一个信息渠道或渠道刷新失败时，刷新进度和错误反馈应准确且不阻塞其他启用渠道。
- 窗口在桌面阈值附近反复缩放时，双栏与单栏切换不得产生状态丢失或渲染异常。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 教务页 MUST 删除完成度卡片、学习档案卡片及详细来源按钮。
- **FR-002**: 教务头部 MUST 合并核心概览与个人摘要，只展示姓名、学号、院系、专业、班级及必要指标，并移除冗余说明和换行容器。
- **FR-003**: 已获学分 MUST 使用全部已通过成绩记录的学分合计；未知数据 MUST 与真实零学分可区分。
- **FR-004**: 下一场考试卡 MUST 与教务概览区域在宽屏对齐，在窄屏完整堆叠。
- **FR-005**: 体育考勤卡 MUST 根据可用宽度调整指标排布，保持与第二课堂学分卡一致的响应式行为。
- **FR-006**: 周课表 MUST 采用星期列、节次/时间轴和跨节次彩色课程块的结构，并允许内容滚动而不发生底部溢出。
- **FR-007**: 信息页 MUST 删除常规控制行及其中的引导说明。
- **FR-008**: 信息来源 MUST 仅分为官网与微信公众号/服务号，教务处归属官网；刷新操作 MUST 默认刷新所有启用渠道。
- **FR-009**: 信息来源面板和分页 MUST 在窄屏中完整显示；页码跳转 MUST 生效并将消息列表定位到顶部，分页区域 MUST 与列表保持清晰间距。
- **FR-010**: 邮件列表 MUST 限制在可视区域内并支持独立滚动，每封邮件只显示时间、标题和发件人。
- **FR-011**: 邮件详情 MUST 限制在可视区域内并支持独立滚动，保留正文段落样式且 MUST NOT 加载远端内容。
- **FR-012**: 邮箱页 MUST 删除搜索框和关于本机读取及桌面/移动布局的说明。
- **FR-013**: 快速跳转 MUST 在卡片内横向排列并自动换行，以减少纵向空白。
- **FR-014**: AI 服务页在宽屏 MUST 将 API Key/访问记录与外部应用授权以窄宽双栏等高显示，在窄屏 MUST 回落为单栏。
- **FR-015**: MCP 服务启停按钮 MUST 位于端口输入栏右侧并保持窄屏可操作。
- **FR-016**: 桌面导航的设置入口 MUST 固定在侧栏底部，现有目的地索引和移动端导航语义 MUST 保持兼容。
- **FR-017**: 受影响页面 MUST 遵循紧凑、操作邻近配置、卡片内滚动的控制台式视觉语言，并复用现有设计系统。

### Key Entities

- **教务成绩记录**: 表示课程学分与是否通过，用于合计真实已获学分。
- **信息渠道**: 表示官网或微信公众号/服务号，以及该渠道是否启用和最近刷新状态。
- **邮件摘要与正文**: 摘要只含时间、标题、发件人；正文为本机可安全展示的文本内容。
- **课程时段**: 表示星期、起止节次、时间、课程名、地点和教师，用于网格定位。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 360×800、768×900、1200×900 三类窗口中，全部 7 个受影响入口均无渲染溢出或不可达操作。
- **SC-002**: 对任意成绩样例，已获学分与全部已通过成绩的学分合计完全一致，未通过成绩不计入。
- **SC-003**: 用户在一次操作内可刷新所有启用的信息渠道，且无需分别触发官网和微信刷新。
- **SC-004**: 包含至少 50 封邮件和长正文的邮箱仍保持在一屏工作区内，列表与详情均可在各自区域查看全部内容。
- **SC-005**: 周课表中课程块的星期与起止节次定位准确率达到 100%，且可在目标窗口尺寸查看全部时段。
- **SC-006**: 所有删除项在可访问语义树和可见界面中均不可见，剩余核心任务可在最多两次交互内完成。

## Assumptions

- “Cockpit Tools”指面向桌面管理控制台的高信息密度布局原则，不要求逐像素复制外部项目。
- 现有本地数据源、认证方式和页面路由保持不变，本轮不新增校园系统写入能力。
- 邮件正文继续使用本机已解析的纯文本；HTML、远端图片、脚本和外部样式均不加载。
- 移动端保留邮件独立详情页，桌面端保留列表—详情并列，但两者均须受视口约束。
