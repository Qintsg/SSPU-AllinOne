# Research: 校园工作台响应式收敛

## 已获学分的权威数据源

**Decision**: 从独立成绩快照中筛选已通过记录并累加学分，教务概览只消费该结果。

**Rationale**: 当前培养方案完成度依赖 overview 内附带的成绩，但生产加载链路中的成绩来自独立成绩请求，导致 overview 无成绩时把所有课程视为未完成并显示 0。成绩快照是“是否通过”和课程学分的直接事实源。

**Alternatives considered**: 把独立成绩重新注入培养方案派生流程会耦合两次请求并扩大竞态面；继续显示完成度值会保留已确认的数据错误。

## 视口约束与滚动所有权

**Decision**: 桌面邮件列表、邮件详情和课表网格拥有各自的滚动容器；页面头和操作保持稳定。窄屏在布局阈值下改为单栏或独立详情。

**Rationale**: 当前自然高度 Column 放入紧约束的 Expanded 中造成底部溢出，并让长内容无限拉长页面。由实际长内容区域持有滚动可保证操作始终可达。

**Alternatives considered**: 整页统一滚动无法满足邮件双栏独立阅读；压缩字体或固定更小卡片高度会牺牲可读性且不能消除根因。

## 周课表视觉模型

**Decision**: 桌面/平板采用固定左时间轴、顶部星期列和基于起止节次定位的课程块；移动窄屏继续按天列表。

**Rationale**: 附件表达的是空间化周视图，课程持续时间必须通过纵向跨度展示。基于二维定位的网格比“每两节一行”的普通列表更准确。

**Alternatives considered**: 简单表格单元无法自然跨节次和处理重叠；所有宽度都强制七列会让手机内容不可读。

## 信息来源和刷新语义

**Decision**: UI 顶层只保留官网、微信公众号/服务号两个来源，教务处归入官网；服务层提供单个“刷新全部启用来源”的运行任务并统一报告进度。

**Rationale**: 教务处是官网内容站点而非独立渠道类型。单次原子任务避免当前运行锁在连续触发两个刷新时拒绝第二个任务。

**Alternatives considered**: UI 顺序调用两个现有刷新方法会被运行锁阻塞；移除运行锁会允许重复请求和状态竞争。

## Cockpit 风格边界

**Decision**: 采用 Cockpit 类管理控制台的原则：高信息密度、短标题、操作紧邻配置、宽屏非对称双栏、内部滚动和稳定底部导航；不逐像素复制第三方产品。

**Rationale**: 用户需要的是一致的工作台体验，现有 Qingyuan 设计令牌必须继续作为视觉事实源。

**Alternatives considered**: 直接复制外部 CSS/控件会破坏多平台 Flutter 设计系统和仓库治理规则。
