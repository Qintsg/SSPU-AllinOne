# Phase 0 Research: 校园服务能力收敛

## 邮件协议与附件

**Decision**: 继续使用 `enough_mail` 处理 IMAP/SMTP/MIME，使用 `file_picker` 选择待发送附件。

**Rationale**: 两者已经进入项目依赖和锁文件，覆盖分页获取、IMAP 标志、MIME 附件与跨平台文件选择；复用它们可避免自制协议解析、编码和平台文件选择逻辑。

**Alternatives considered**: 自行拼接 IMAP/SMTP 命令和 MIME；因边界条件、编码、安全与维护成本过高而拒绝。只使用 POP3；因无法可靠回写 `Seen` 且分页能力受限而拒绝。

## 本地通知与提醒时间

**Decision**: 使用 `flutter_local_notifications` 统一平台通知，使用 `timezone` 生成带本地时区语义的计划时间，由应用内协调器负责取消和重排。

**Rationale**: 依赖提供多平台通知通道、权限和计划投递能力；独立协调器可以把模块开关、勿扰和事件变化与平台插件隔离。

**Alternatives considered**: 保留 Windows-only 通知包；无法覆盖目标五端。每次刷新直接创建通知；容易产生重复计划且难以可靠取消。

## 日历导出与系统导入

**Decision**: 应用生成标准文本日历文件，使用 `open_filex` 交给系统关联应用处理导入，不直接写系统日历数据库。

**Rationale**: 文件交换跨平台、可审计且保留用户确认；现有依赖已经提供系统打开能力，不需要额外日历权限。

**Alternatives considered**: 为每个平台直接写入系统日历；权限、重复事件和平台差异显著，且偏离用户明确的文件导入路径。

## 首页模块控制

**Decision**: “是否显示”与“是否获取”保持两个独立偏好；模块获取开关在服务入口、手动/自动刷新、详情页和提醒协调器处共同执行。

**Rationale**: 隐藏卡片是展示偏好，停止获取是隐私和网络行为，二者合并会让用户无法预测后台访问。

**Alternatives considered**: 隐藏即停止获取；会破坏详情页、通知或其他入口的合理使用。仅在 UI 禁用按钮；无法阻止后台刷新。

## 微信公众号与服务号

**Decision**: 服务号不建立独立刷新任务，继续复用公众号平台认证、账号配置、文章抓取、去重和通知意愿链路。

**Rationale**: 两者在当前管理平台入口和文章获取流程中没有需要分叉的协议边界，统一链路能避免重复认证与重复通知。

**Alternatives considered**: 为服务号增加单独定时器或配置页；会产生竞态、重复消息和额外维护成本。

## macOS 发布

**Decision**: 正式产物必须完成 Developer ID 签名、公证、装订、Gatekeeper 校验和 universal 架构检查；任一步骤缺少材料或失败即中止发布。

**Rationale**: 仅构建或临时签名不能证明最终用户可在默认安全策略下启动应用。

**Alternatives considered**: 发布未签名应用并要求用户手动放行；不满足 #327。只验证工作流文本；不能替代 Runner 与真实安装验证。

## 数据与平台边界

**Decision**: 状态和缓存继续存储在平台默认应用数据目录，账号密码、Cookie、Token 留在系统安全存储；所有校园系统访问保持只读。

**Rationale**: 与项目宪章、隐私文档和现有迁移路径一致。

**Alternatives considered**: 将凭据混入普通 JSON 或同步目录；会扩大泄露面并违反仓库强制约束。

## 通知权限与消息意愿

**Decision**: 普通消息通知作为独立本地偏好保存；设置页读取系统权限并展示明确状态，教务提醒协调器只在权限明确拒绝时清空计划，查询异常保持 `unknown` 并允许用户刷新。

**Rationale**: 全局通知、课程/考试提醒和普通消息是不同的用户意愿；把它们拆开可以避免用户只想关闭某类通知时误停其它能力。权限状态必须区分“拒绝”和“暂时无法查询”，否则会误导恢复路径。

**Alternatives considered**: 复用全局开关控制普通消息；无法满足独立控制需求。查询异常按已允许处理；可能在系统拒绝时继续创建无效计划。

## 教务错误状态恢复

**Decision**: 详情页使用保留式刷新控制器；培养计划空数据、登录失效和网络失败均提供原位重试，空闲教室失败时显示错误反馈并保留最近一次有效列表。

**Rationale**: 教务网络波动常见，清空已展示结果会造成用户误以为数据不存在；保留旧结果同时标明其时效性更符合可恢复查询体验。

**Alternatives considered**: 失败后统一清空页面并只显示错误；状态容易闪白且用户无法继续比对上一次结果。
