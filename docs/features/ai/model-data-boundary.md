## 1. 需求

承载 AI 的**模型来源（BYOK）**与**数据边界（默认不出域 + 按需授权最小必要）**，使「数据本地不上云」原则在引入 AI 后仍可控、可审计。

**验收要点**
- 用户自配 OpenAI 兼容端点/Key/模型名；Key 进系统安全存储。
- 数据默认不出域；每类只读数据出域需显式授权、最小必要。
- 未配置模型或未授权时，AI 能力优雅不可用，不静默出域。

## 2. 模型来源（BYOK · OpenAI 兼容）

- 用户填写：**Base URL（端点）+ API Key + 模型名**。
- 兼容 OpenAI Chat Completions 协议，可对接 OpenAI、各类代理，以及本地 Ollama / LM Studio / vLLM 等。
- API Key 进系统安全存储（`flutter_secure_storage`），不写 `app_state.json`、不进日志。

## 3. 数据边界与授权

- **默认不出域**：AI 默认不读取任何敏感数据。
- **工具按需取数**：各域注册**只读**工具；模型请求时，应用校验该域/工具的授权开关 → 返回**最小必要**字段 → 随请求出域。
- **授权粒度**：按域/工具的开关（用户可见可控）；写操作工具不存在。
- **透明可审计**：出域前提示，对话中展示调用了哪些工具、取了哪些数据。

```
授权矩阵（示例）
  grade            : [ ] 允许 AI 读取
  calendar         : [ ] 允许 AI 读取
  message-center   : [ ] 允许 AI 读取
  campus-card      : [ ] 允许 AI 读取
默认全部关闭；用户逐项开启。
```

## 5. 约束

- 上云边界**显式定义、用户可控**：数据仅在用户开启 AI、配置模型且授权对应域时出域。
- 写操作工具不注册；AI 不具备任何写能力。
- Key/出域内容不进日志与普通缓存；对话历史本地、可清除。
