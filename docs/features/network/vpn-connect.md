## 1. 需求

> 归档说明：#169 已因权限原因以及学校开放 5G 融合专网而按 `not planned` 关闭。以下内容仅保留为历史设计记录，不是当前实现计划。

让桌面校外用户一键连接学校 VPN 以访问受限校园服务，并配合门禁实现「按需自动连接」。连接能力由放入本地 `plugins/` 的 VPN 插件提供（见 [本地插件机制](plugin-host.md)），应用只负责编排状态、策略与 UI。

**验收要点**
- 仅桌面；Android/iOS 不提供 VPN。
- 仅在「校外·未连接」且 VPN 入口可达时可开启；校园网内、已经过外部 VPN、VPN 入口不可达时**不可开启**。
- 无可用 VPN 插件时，VPN 表现为「不可用」，**但 UI 不解释原因为缺少插件**。
- 手动开启→显示连接进度；手动关闭→明确停止。
- 门禁触发：访问受限服务且不在内网、且启用自动连接时尝试连接。

## 2. 交互与界面（历史方案）

- UI 只暴露**状态语义与动作**：连接中 / 已连接 / 未连接 / 不可用 / 错误，以及连接/断开动作。
- 连接进度、断开原因、不可开启原因可见；不可用时给出中性提示（如「当前不可用」），**不提及插件/来源**。
- 设置页「VPN 自动连接」开关（默认关闭），归 [设置中心](../platform/shell/settings.md)。
- VPN 状态/开关组件可由插件经 [本地插件机制](plugin-host.md) 的 `registerComponent` 提供，或由应用自带；二者皆不在 UI 暴露插件存在。

## 3. 实现

### 3.1 分层

```
受限服务调用方 ─→ 网络门禁 ensureReachable() ─→ VPN 协调服务
                                                      │
                                    本地插件机制（plugin-host）
                                      ├─ executeFile      → 独立进程 + stdio JSON-RPC
                                      └─ registerComponent → VPN 状态/开关组件
                                                      │
                              用户手动置入 plugins/ 的 VPN 可执行产物（桌面）
```

- **VPN 协调服务**（network 内新增）：封装可开启判定、状态机、错误分类、门禁编排；不直接执行文件，经 [本地插件机制](plugin-host.md) 的 `executeFile` 拉起 VPN 进程并以 stdio JSON-RPC 交互。
- 无 VPN 插件时协调服务上报「不可用」。

### 3.2 状态机（本期简化）

本期先实现四态，**重连策略后补**（见待办）：

```
未连接 ──connect()──▶ 连接中 ──成功──▶ 已连接
   ▲                    │                │
   └────失败/出错───────┴── error ◀──────┘（异常）
                                         │
                          disconnect() / 进程退出 → 未连接
```

| 状态 | 含义 |
| --- | --- |
| 未连接 | 隧道未建立 |
| 连接中 | 正在经插件进程建立隧道 |
| 已连接 | 隧道可用（对应网络状态 `vpnPlugin`） |
| 错误 | 连接失败或运行中异常，附错误分类与可读提示 |

> #169 的完整状态（不可用 / 断线）与断线原因分类（被踢、1h 无操作、服务器异常、网络切换、进程退出、手动关闭）及自动重连策略（仅「1h 无操作」在启用自动连接时重连，其余不重连直到手动开启）作为**后续演进**纳入。

### 3.3 可开启 / 自动关闭判定

依据 [网络状态 6 态](network-status.md)：

| 当前状态 | 可开启 VPN | 说明 |
| --- | --- | --- |
| `outsideUnconnected` + VPN 入口可达 | ✅ 可开启 | 唯一可开启场景 |
| `outsideUnconnected` + VPN 入口不可达 | ❌ 且自动关闭 | DNS/服务器异常等，给中性提示 |
| `campus` | ❌ | 校园网内无需 VPN |
| `vpnExternal` | ❌ | 已有外部 VPN 可达，尊重现有连接 |
| `offline` / `unknown` | ❌ | 无网络或未确定 |
| 无可用 VPN 插件 / 非桌面 | ❌（不可用） | 中性提示，不提插件 |

### 3.4 门禁集成

受限服务请求前调用 `ensureReachable(allowAutoConnect:)`：

- 已在 `campus / vpnExternal / vpnPlugin` → 直接放行。
- `outsideUnconnected` + VPN 入口可达 + 启用自动连接 + 桌面有可用 VPN 插件 → 经协调服务连接后放行。
- 未启用自动连接 / 不可开启 / 无插件 / 非桌面 → 返回需手动处理，提示用户（中性文案）。

### 3.5 许可证与隔离

- 应用**不下载、不分发、不内嵌** VPN 可执行产物；由用户手动置入本地 `plugins/`。
- VPN 可执行以**独立进程**运行（进程隔离），主仓库不复制、不改写、不内嵌其源码。
- 上述边界使应用与外部 VPN 实现的许可证（如 AGPL）保持隔离；细节见 [本地插件机制](plugin-host.md)。
