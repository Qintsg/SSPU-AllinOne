## 1. 需求

在用户怀疑「连不上某服务」时，提供一键体检：对内网各服务逐项探测可达性并测速，定位是网络环境问题、单个服务问题，还是需要连 VPN。

**验收要点**
- 一键对预置内网服务清单逐项体检，输出每项可达/不可达 + 往返耗时。
- 体检结果与当前 [网络状态 6 态](network-status.md) 一并呈现，给出可读结论。
- 失败项给出方向性建议（如「需连接校园网或 VPN」）。

## 2. 范围（本期）

| 能力 | 是否纳入 | 说明 |
| --- | --- | --- |
| 内网服务逐项体检 | ✅ | 教务 / 校园卡 / 邮箱 / VPN 入口 / 校园站点等逐项探测 |
| 延迟 / 连通性测速 | ✅ | HTTP 往返耗时，辅助判断网络质量 |
| Portal / 认证页检测 | ❌（后续） | captive portal 劫持检测，暂不纳入 |
| 一键导出诊断报告 | ❌（后续） | 脱敏报告导出，暂不纳入 |

## 3. 交互与界面（规划）

- 一键「开始体检」，逐项流式展示进度与结果（可达/不可达、耗时）。
- 顶部呈现当前网络状态结论；底部给出整体建议。
- 未来界面必须使用清源组件；本文档只约束**体检项语义与结果结构**。

## 4. 实现

### 4.1 体检项

- 预置内网服务清单（域名可配置）：教务网关、校园卡、邮箱、`vpn.sspu.edu.cn`、`tygl.sspu.edu.cn` 等。
- 复用 `network-status` 的探针基座（只读 GET + 超时），为每项记录：可达性、HTTP 状态、往返耗时、错误说明。

### 4.2 结果结构

```
DiagnosticsReport
  ├─ accessMode（当前网络 6 态）
  ├─ items: [ { name, target, reachable, statusCode?, latencyMs?, detail } ]
  └─ conclusion（按状态与失败项聚合的可读建议）
```

- 测速取多次往返中位数/均值，避免单次抖动误导。
- 体检并发受限以免对校园站点造成压力。

## 5. 关联

- 依赖：[网络状态检测](network-status.md)（共享探针基座与当前状态）。
- 被依赖：用户主动排障入口；可作为 VPN/门禁失败时的「进一步诊断」跳转目标。

## 6. 约束

- 探测仅只读 GET，不携带凭据；并发与频率受限。
- 结果不含任何敏感信息；后续若做导出报告需脱敏。
