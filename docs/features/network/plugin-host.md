# 本地插件机制

> 模块：[校园网](README.md)　·　状态：**设计中**

## 1. 需求

提供一个**本地插件宿主**：扫描应用数据目录下 `plugins/` 文件夹中由用户**手动放入**的插件并加载其能力，当前仅支持「网络 VPN」。应用不下载、不分发、不内嵌任何插件产物，**应用内不出现任何与插件/来源相关的提示或入口**。

**验收要点**
- 桌面扫描 `plugins/` 文件夹，识别并加载提供 VPN 能力的插件。
- 缺少插件时，VPN 功能表现为「不可用」，**但 UI 不提及插件/来源/放置方式**。
- 移动端不加载插件、不暴露下述方法，VPN 直接不支持。

## 2. 插件目录

- 桌面：**系统默认应用数据目录**下的 `plugins/` 子目录（由 `path_provider` 提供，如 Windows `%APPDATA%/<app>/plugins/`、macOS 沙盒容器内、Linux `$XDG_DATA_HOME/<app>/plugins/`）。
- 由用户**手动**放入插件文件，应用既不创建下载入口、也不在 UI 内说明该目录。
- 宿主在启动或按需时扫描该目录完成发现。

## 3. 暴露给插件的方法（核心）

宿主向插件暴露以下能力，插件据此接入应用：

### 3.1 添加组件 `registerComponent`

- 插件向宿主注册 UI 组件，挂载到预置**扩展点**（当前为 VPN 开关/状态区）。
- 宿主在对应扩展点渲染插件提供的组件；组件经设计系统约束的容器承载。
- 扩展点为有限白名单，插件不能任意注入到全局 UI。

### 3.2 执行文件 `executeFile`

- 插件请求宿主执行指定文件（如 VPN 可执行产物）。
- 宿主**按平台拉起独立进程**，返回进程句柄与 IO 通道（stdio）；按需启动、空闲回收。
- 进程隔离：插件可执行以独立进程运行，不内嵌进主程序（许可证/稳定性隔离）。

> 方法集保持精简，仅服务 VPN；未来若扩展更多能力再增补，本机制设计为可扩展但当前不通用化。

## 4. 实现

```
plugins/ 文件夹  ──扫描──▶  插件宿主  ──┬─ registerComponent → 渲染到 VPN 扩展点
（用户手动放入）                        └─ executeFile      → 独立进程 + stdio
                                                              │
                                              VPN 协调服务消费（见 vpn-connect.md）
```

- 宿主与插件经约定通道交互（stdio）；状态/事件可脱敏记录。
- 平台判断：仅桌面注册扩展点与执行能力；移动端宿主为空实现。

## 6. 约束

- **应用内 UI/文案零提及**插件、来源、仓库、放置方式；无下载、无管理页。
- 应用不下载、不分发、不内嵌插件产物；插件为用户手动置入的本地文件，进程隔离运行。
- 移动端不支持：不扫描目录、不暴露方法。
- 敏感信息（凭据/会话）不进日志或持久化状态。
