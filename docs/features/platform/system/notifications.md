## 1. 需求

统一通知投递与提醒（#188）：课程/考试提醒、新消息推送，受全局开关与勿扰时段约束。**info 只产消息并声明通知意愿，投递在此实现**。

**验收要点**
- 基于课表/考试的本地定时**课程/考试提醒**。
- **新消息推送**：消费 [消息中心](../../info/message-center.md) 的新消息与单源（含单公众号）通知意愿。
- **勿扰时段**：DnD 时间段内不打扰；全局推送开关。

## 3. 当前实现

- `AcademicReminderPlanner` 按校历、周次/单双周、节次和考试时间生成未来 45 天的稳定提醒计划；考试缺少明确时间时跳过，不猜测默认时刻。
- `AcademicReminderCoordinator` 从当前账号的课表/考试缓存读取数据；应用启动、缓存更新、学期或相关设置变化时串行重建计划，教务模块停止获取时立即清空计划。
- `NotificationService` 使用 `flutter_local_notifications`：Android、iOS、macOS、Windows 支持即时与定时通知，Linux 支持即时通知并明确降级为不提供持久化定时调度。课程和考试时间统一按 `Asia/Shanghai` 墙上时间调度，不受设备当前时区平移。
- 设置中心提供通知总开关、普通消息通知、课程提醒、考试提醒、两类提前量与勿扰时段；课程可选提前 5/15/30/60 分钟，考试可选提前 1/6/12/24/48 小时，修改后立即重排。首次启用任一通知能力时请求系统权限，并在设置页提供权限状态查询/刷新。Android 已声明重启后恢复计划所需接收器。
- 新消息自动刷新链路在投递前检查通知总开关、普通消息开关、勿扰时段和单公众号通知意愿；任一条件关闭都不会产生系统通知，但仍可保存消息供消息中心查看。
- 教务提醒协调器在系统权限明确拒绝时清空旧计划并返回 `permissionDenied`，权限恢复后由设置页同步重排；查询失败会显示未知状态，不把未知误报为已授权。
- 同一刷新批次的消息在通知前按稳定 ID 去重，避免分页重叠或重复来源造成重复提醒。

## 5. 约束

- 投递受全局开关与勿扰约束；尊重 info 的单源通知意愿。
- 通知内容不含敏感明文；不在启动时无条件推送。
