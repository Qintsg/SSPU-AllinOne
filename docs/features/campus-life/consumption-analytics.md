## 1. 需求

基于校园卡交易明细，提供**只读**的消费时间趋势可视化，帮助用户直观了解一段时间内的消费变化。

**验收要点**
- 以**单个时间趋势图（柱状/折线）**展示消费金额随时间的变化。
- 支持选择时间窗（如近 7 天 / 近 30 天 / 自定义区间）。
- 纯本地计算，不额外联网；无可用明细时给出空态。
- 只读分析，**不涉及任何写操作**。

## 3. 交互与界面

- 一张时间趋势图（柱状或折线），X 轴为时间桶（按日/周/月，依时间窗自动选择），Y 轴为消费金额。
- 时间窗切换控件；空态/数据不足提示。
- 使用清源图表容器、时间窗控件与空态；本文档约束**统计语义与图表数据结构**。

## 4. 实现

### 4.1 数据来源

- 复用 [校园卡](campus-card.md) 去重合并后的本地交易明细缓存（`CampusCardTransactionRecord`）。
- **纯本地计算**，不触发额外联网；明细的获取/同步仍由校园卡功能负责。

### 4.2 计算

```
缓存交易明细（去重合并）
   └─ 按时间窗过滤
        └─ 按时间桶（日/周/月）聚合消费金额
             └─ TrendSeries { buckets: [ { bucketStart, totalAmount, count } ] }
```

- 仅统计消费（支出）类记录；页面提供按日、按周、按月的显式粒度切换，避免自动切换导致用户误读。
- 金额聚合避免浮点误差（按分计算或定点）。
- 有流水号的记录按稳定交易 ID 去重；缺少流水号时使用完整稳定字段签名，避免把同日同额但实际不同的消费误合并。
- 自定义开始日期晚于结束日期时拒绝条件并保留上一次有效趋势，不用无效输入覆盖当前结果。

当前实现采用按分聚合的 `TrendSeries`，页面提供全部、近 7/30 天及自定义日期范围，并支持按日、按周、按月切换；不引入图表依赖，使用清源绘制层保证五端一致。

## 6. 约束

- 只读分析，不写、不联网（数据来自本地缓存）。
- 统计结果不含敏感信息；数据全本地。
- 无明细或明细不足时降级为空态，不报错。
