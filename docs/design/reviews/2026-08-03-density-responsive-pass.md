# 清源密度与响应式第一轮设计评审

> 状态：主页、真实 8 分区结构下的“常规”设置及“安全”连续工作台已冻结；其余设置任务页继续按批评审。

## 范围

- 第一批：主页、设置总览、账户与连接、首页与通知、数据与隐私、微信公众号认证、应用更新。
- 五个平台共享信息层级；平台差异只影响窗口安全区、输入方式和系统外部边界。
- 视觉回归门槛为每张截图 SSIM ≥ 0.90，但新稿的美观、便利与完整状态优先于旧基线相似度。

## 当前画面问题

1. 360×800 与 768×900 的主页把概览卡纵向堆到时间轨之后，首屏无法看完。
2. 时间轨的标题、内边距和三条记录共同自然增高，窗口越窄越像一张占满页面的海报。
3. 四个同层服务摘要各自使用大圆角卡，造成重复边框、过多卡间距和无信息留白。
4. 常用入口和部分设置操作的按钮视觉框大于文字与图标的实际需要。
5. 设置账户的设计参考、视觉 fixture 与真实运行结构不一致；错误态仍在复用通用三行占位模板。
6. 紧凑设置页使用横向标签时会截断最后分区，恢复路径不够直接。

## 候选决策

- 主页改为“固定首屏骨架”：标题和状态固定上限，时间轨占弹性主区，摘要合并为统一概览面板，常用入口进入紧凑行动坞。
- 360 默认文字缩放不滚动；大字号无障碍模式允许滚动并保持完整语义。
- 768 不再退化为全单列；时间轨与概览保持双栏，底部行动坞跨栏。
- 概览项只在整个面板外使用一次边框，内部用分隔线与业务色图标区分。
- 设置首页只展示状态与统一管理入口；凭据编辑、认证、清除、下载等进入专用任务页。
- 紧凑设置分区使用单个“当前分区”选择器打开底部抽屉；中屏使用顶部标签，宽屏使用左侧分区导航。
- 360–899 使用分区抽屉，900–1199 才使用顶部标签；768 不再因 8 个标签而截断“关于”。
- 常规分区按“首页显示 → 消息推送 → 应用体验”排列；窗口、外观和更新合并为紧凑入口区，但不删除任何设置语义。
- 文本按钮与图标按钮保留 48dp 命中区，但可见边框按 36–44dp 内容高度绘制。
- 首页的 8 个既有显示项继续保持独立语义，只按“时间与学习 / 校园服务”分组；否决将其合并为 3 个组合开关的候选方案。
- 首次进入、加载和首次失败使用内容自适应恢复面板，不以等高大卡填满剩余视口。
- 宽屏设置导航不再包裹外层大卡；只有 compact 分区触发器和 medium 标签条保留必要的表面边界。

## 功能级可见调整门禁

增删按钮、卡片、设置项或改变可设置粒度，都属于设计变更而非实现细节。每项必须依次完成：

1. 在 HTML 原型和机器可读视觉清单中表达内容态、禁用态、失败态与恢复路径。
2. 自评审信息层级、操作协同、误触风险、可逆性、键盘/触控/读屏和四档响应式。
3. 记录保留或否决理由并冻结版本化截图；冻结后才允许修改 Flutter。
4. 实现不得通过重录基线改变已冻结语义；确需改变时退回步骤 1。

本轮评审否决了“8 项首页显示设置合并成 3 项”的方案，因为它会删除用户独立隐藏邮箱、体育、校园卡等内容的能力。最终稿只优化视觉分组，不改变存储键与行为契约。

## 动效审查

- 动效只解释状态连续性：数值换代、操作锁、弹层来源、列表增删和路由层级。
- 不使用持续漂浮、无业务含义的卡片入场或窗口缩放时大范围补间。
- 所有异步完成结果绑定 service、账户、来源和页面代次；过时代次不得触发动效或反馈。
- `disableAnimations` 下位移、缩放和循环旋转归零，状态仍通过文字与语义 live region 可见。

## 外部参考结论

- Wonderous 将屏幕尺寸、`disableAnimations` 和样式尺度集中到应用样式层，并让状态切换使用明确 key 的短时 `AnimatedSwitcher`；清源采用“集中密度模式 + 减少动态”原则，不复制其视觉资产。
- Flutter Vignettes 的成熟示例会用可用高度比例限制主视觉，并在横竖屏改变信息编排；清源采用“宽度 + 高度共同选密度”的原则，不复制其 Material 组件或演出效果。
