# 校园卡空记录恢复条评审 v01

日期：2026-08-19  
分支：`feature/design-language-spec`  
状态：已实现并完成本机 Windows 视觉与行为核验

## 评审范围

评审 [校园卡空记录恢复条 v01](../patterns/campus-card-empty-recovery-v01.md)，覆盖校园卡详情的本地筛选空状态；不评审余额、交易详情、远端查询、同步、分页和终端错误。

## 评审结论

- [x] 新方案把短的空结果从居中高卡收束为内容高恢复条，消除了宽屏中无意义的卡内空白。
- [x] 360 保留垂直阅读与 48dp 行动目标；768 以上恢复条同行，避免大屏把局部筛选结果误读为页面主内容。
- [x] 清除操作仍明确是本地筛选恢复，不会被设计成“重新查询”或“同步”这类远端动作。
- [x] 保留一个清晰的边界、语义标题和现有主题焦点/减少动态契约；没有新增图标包、颜色、卡片、设置项或服务状态。
- [x] 方案与既有“随身账本”方向一致：余额用于确认可信度，交易账本与恢复条用于完成筛选任务。

## 风险与实施约束

1. 横向布局不能把长说明压到不可读，也不能让“清除筛选”缩小到 48dp 以下；必要时必须自然换行。
2. 仅 `empty` 状态采用此恢复条。无可恢复记录的 `error` 仍需给出明确的远端重试与返回路径。
3. Flutter 实现完成后，以当前源码重新采集四档亮暗截图，并运行校园卡详情行为回归；不得用改录旧截图代替验证。

- 交易过滤、`_clearFilters` 本地恢复、远端查询/同步、终端错误、数据模型和路由均未变更；新回归覆盖宽屏左缘对齐、内容高度和 48dp 行动目标，以及紧凑端纵向阅读顺序。
