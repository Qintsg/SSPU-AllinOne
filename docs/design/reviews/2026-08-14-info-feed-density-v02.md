# 校园资讯密度与操作协同 v02

## 设计稿

- HTML 原型：`docs/design/patterns/samples/app-shell.html` 的 `info` 页面。
- 样式：`docs/design/patterns/samples/_app-shell.css` 的资讯两栏、来源条与筛选入口规则。
- 冻结截图：`build/design-review-info-feed-density-v02`，48 张。

## 自评审

- [x] 360×800 的筛选入口固定可见，不需要先横向滚动，也没有增加边框按钮。
- [x] 360 来源条保留横向漫游；内容卡片在底部导航上方自然滚动，无横向溢出。
- [x] 768×900 同行显示四个来源和“更多筛选”，不换行、不挤压刷新或搜索。
- [x] 1200×900 与 1600×1000 使用来源窄列和资讯主列，来源卡与三张资讯卡整体高度接近，避免大片无任务空白。
- [x] 文章卡只保留来源、时间、标题和两行摘要，不增加装饰按钮或重复卡片层级。
- [x] `initial/loading/content/empty/stale/error` 六态均完成亮暗目视检查。
- [x] `stale` 保留搜索、筛选与三条缓存内容；无缓存错误和无认证来源提供不同下一步。
- [x] 来源按钮、刷新、搜索、筛选与状态动作通过 48dp 目标门禁；来源方向键、清除筛选与焦点语义通过浏览器交互核验。
- [x] 减少动态环境下页面动画关闭，颜色与字号全部来自清源 token。
- [x] 页面辨识度来自校园资讯的“来源—时间”结构，不依赖通用仪表盘、渐变数字卡或无意义装饰。

## 冻结决定

v01 在 360 宽度把高级筛选放在横向滚动末端，入口发现性不足，因此未冻结。v02 将无边框“筛选”固定在来源条右侧后通过自评审并冻结。Flutter 只能在此版本冻结后开始调整；若后续改变按钮、卡片、筛选项或状态文案，必须先产生新的设计版本和评审记录。

- 对比报告：`build/visual-results/windows-info-feed-density-v02/report.json`。
- 结果：48/48 通过，最低 SSIM `0.956009707749558`。
