# 首页服务摘要排序 v01

## 对象与任务

- 使用者：希望把最常看的校园服务放到首页摘要最前面的学生。
- 单一任务：在设置页同时看清“是否显示”和“显示顺序”，并理解隐藏不会自动停止后台联网。
- 边界：只排序培养方案、校园卡、学校邮箱和体育考勤；今日学程时间轨与底部行动坞保持固定。

## 布局

```text
首页显示
  时间与行动
    [图标] 今日学程时间轨                     [开关]
    [图标] 最近校园待办                       [开关]
    [图标] 第二课堂                           [开关]
    [图标] 常用入口                           [开关]

  服务摘要
    排序只改变位置；联网刷新在“自动刷新”中控制
    [图标] 培养方案      第 1 位 · 显示中     [上][下][开关]
    [图标] 校园卡余额    第 2 位 · 显示中     [上][下][开关]
    [图标] 学校邮箱      第 3 位 · 显示中     [上][下][开关]
    [图标] 体育考勤      第 4 位 · 显示中     [上][下][开关]
```

360px 下操作组落到标题下方并右对齐；768px 起与标题同排。首项上移和末项下移禁用，所有有效操作保持不小于 48dp，按钮必须有包含服务名的语义标签。

## 设计取舍

- 使用现有清源暖灰表面、墨蓝结构、青雾响应色和 MiSans，不新增色彩、字体、圆角或阴影 token。
- 顺序是用户真正需要理解的信息，因此显示“第 N 位”，不使用无语义编号装饰。
- 不采用仅拖拽交互。开源 `UCSD/campus-mobile` 在无障碍导航中使用上移/下移按钮；清源将这一明确、可键盘操作的路径作为五端默认。
- 不把显示开关与自动刷新合并。显示控制信息层级，自动刷新控制后台联网，两者继续分别持久化。

## 状态与兼容

- 旧版本没有顺序配置时使用培养方案、校园卡、邮箱、体育考勤的当前顺序。
- 持久化数据中的未知项与重复项会被忽略，新版本新增项追加到末尾。
- 页面恢复顺序时尊重减少动态；关闭动画时不创建零时长尺寸动画容器。
