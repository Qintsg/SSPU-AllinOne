## 用户与单一任务

对象是需要通过学校 SMTP 发送一封普通文本邮件的学生。单一任务是：填写收件人、主题和正文后，随时清楚地取消或提交，而不是在长表单底部寻找操作。

## 视觉方向

本页采用“**连续书写页，而非卡片里的第二个页面标题**”。页面标题已经说明“撰写邮件”，表单卡只保留 `SMTP 主动发信` 的边界说明，去除重复标题和关闭图标。色彩、排版和尺寸继续只来自清源 token：纸白 `neutral.surface`、正文墨 `neutral.fg`、边界灰 `neutral.border`、清源青 `brand.strong` 与 MiSans 正文/辅助层级。

唯一的功能性特征是紧凑端提交坞：它是一条有上分隔线的轻量行动区，不是浮动卡或第二层大按钮框。

```text
360 / 768
┌ 页面标题：撰写邮件 ┐
├ SMTP 主动发信 / 发送边界 ─┤
├ 收件人、抄送、密送、主题、正文 ┤
│  错误说明（如有，原位保留）      │
└──────────────────────────────┘
────────────────────────────────
              [取消] [发送邮件]   ← 固定在可视区域

1200 / 1600
┌ 页面标题：撰写邮件 ┐
├ SMTP 主动发信 / 发送边界 ─┤
├ 收件人 ────────────────────┤
├ 抄送 ──────────┬ 密送 ─────┤
├ 主题 / 正文                    ┤
└──────────────── [取消][发送] ┘
```

## 响应式与协同

- 小于 `breakpoint.medium` 时，提交坞位于页面滚动区之外、系统/应用导航之前；无需离开当前输入位置即可取消或发送。
- 768px 及以上不增加固定坞，操作位于按内容结束的表单底部，避免桌面上再增加一条无信息横条。
- 收件人、抄送、密送、主题、正文、地址解析、发送服务和成功后的清空/返回行为不变；只有行动区的位置变化。
- 正在发送时字段、取消和发送共同禁用，避免“表单不能编辑但仍可退出”的歧义；失败结果及其恢复说明保留在正文之后。
- 固定坞内的取消保持次级操作，发送邮件保持唯一主操作；两个命中目标均不少于 48dp，且不强制等宽。
- 键盘顺序保持字段 → 取消 → 发送。键盘或读屏环境不会因视觉上的固定定位改变动作顺序；减少动态时立即显示/移除提交坞。

## 设计自评审

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 保留双“撰写邮件”标题和底部滚动操作 | 否决 | 360×800 首屏重复说明占用输入空间，提交动作离正在编辑的正文太远。 |
| 将所有操作改为顶栏图标 | 否决 | 图标无法清晰表达不可撤销的 SMTP 提交，也不适合发送中的禁用反馈。 |
| 连续表单加紧凑端提交坞 | 采用 | 只在表单会自然超过首屏的断点增加持续可达的操作，不向宽屏引入额外空白。 |

## 验收条件

- 360×800、768×900、1200×900、1600×1000 的亮暗主题下无横向溢出；紧凑端首屏不再出现重复“撰写邮件”标题。
- 紧凑端无论滚动位置，取消与发送操作均可见并可聚焦；发送中二者及全部字段均禁用。
- 宽屏表单维持内容高度与抄送/密送双列，不出现额外的固定操作横条。
- SMTP 发送、地址解析、错误保留、取消、成功清空、导航、减少动态和语义回归不变。
