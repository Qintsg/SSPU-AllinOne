## 目标

对象是进入校历页后本地还没有任何学期档案、正在读取本机缓存并检查公开来源的学生。旧实现只在内容区放一条约 160dp 宽、无标题的居中进度条，360px 首屏出现大片无信息空白，与首页、邮件等其它页面的“活动环 + 标题 + 说明”加载账本不一致。

本稿只调整初始加载的呈现，不改变校历服务、学年/学期保存、PDF 渲染、外部打开、下载、来源文本、状态文案、刷新单飞或失败恢复。

## 视觉方向

- 沿用清源结构蓝/松石状态色、MiSans 与现有 `YhRing.activity`、`YhCard` token；不引入新图标、新动画时长或装饰插画。
- 加载账本与既有“任务状态收束 v01 / 教务详情恢复账本 v01”一致：活动环与文本列相邻、左对齐；标题一行、说明自然换行；无操作按钮（加载中不提供虚假入口）。
- 360px 占内容列；768px 及以上左锚定、收束为 `layout.formContentWidth`，不把短提示拉成整页。

```text
360px                                     768px / 宽屏
┌ ⟳ 正在读取校历                  ┐      ┌ ⟳ 正在读取校历         ┐
│   正在读取本机档案并检查公开来源；│      │   正在读取本机档案并检查  │
│   当前学年与 PDF 将保持可追溯。  │      │   公开来源；当前学年与 PDF │
└─────────────────────────────────┘      │   将保持可追溯。          │
                                         └──────────────────────────┘
```

- `loading` 期间不显示“重试”或“刷新”假操作；页面标题与返回按钮保持可用。
- 加载完成后进入既有 content / empty / error 分支，编排与状态文案一律不变。

## 自评审

1. **保留纯进度条**：否决。360px 一条 160dp 横条悬在空内容区中间，读屏与视觉都不能说明“在加载什么”。
2. **添加整页骨架屏**：否决。校历首帧结构与学期/PDF 强相关，骨架会承诺未加载的布局，且需要新增骨架 token。
3. **采用活动环 + 标题 + 说明的加载账本**：采用。与首页、快捷入口、教务详情的 loading 模式一致；只补状态语义，不伪造内容。

## 实现边界

仅修改 `AcademicCalendarPageLayout._buildBody` 中 `_isLoading && _entries.isEmpty` 分支的返回体：用 `_AcademicCalendarLoadingLedger`（活动环 + 标题 + 说明，内容高、左锚定）替换居中的 `YhProgressBar`。保留加载结束后的全部既有分支与业务契约。

实施后需验证四档亮暗 loading 截图、活动环语义标签、无假操作、减少动态、无横向溢出，并跑全量测试与视觉产物校验。
