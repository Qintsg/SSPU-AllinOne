# 外观选择密度 v01

## 目标

外观页的任务是让学生快速选择跟随系统、亮色或暗色，并确认该选择会即时生效。三个选项本身就是完整的互斥控件；不能再用一张填满视口的外卡制造“还有设置未显示”的错觉。

## 视觉方向

- 保持清源既有的松石选中态、MiSans、`YhSegmented`、来源条和主要行动，不引入新颜色、图标、文案或设置项。
- 本批签名为“主题选择线”：单个分段控件作为唯一边界，直接承接来源条，宽屏左锚定；删除其外层重复卡片和由任务页最小高度造成的空白。
- `YhSegmented` 的单选语义、箭头键、Tab 顺序、hover、焦点和按压效果是核心交互，布局调整不得将它包进水平滚动容器而削弱键盘连续性。

## 响应式编排

```text
360 / 768                              1200 / 1600
┌ 标题、说明、应用主题 ┐               ┌ 标题、说明 ───── 应用主题 ┐
├ 来源条                ┤               ├ 来源条 ───────────────────┤
└ [跟随系统 | 亮色 | 暗色] ┘            └ [跟随系统 | 亮色 | 暗色]  │
```

- 360px：主要行动保持整行；三项选择在一个紧凑分段内完整可见，无横向滚动和裁切。
- 768px、1200px、1600px：来源条沿用任务页页面骨架；选择线按固有内容宽度左锚定，右侧留白回归背景。
- 主题切换后保持原选择位置、来源条和主要行动，不产生布局跳跃；现有主题即时生效与“应用主题”回到设置上下文的行为不变。
- 减少动态时由现有组件直接完成状态变化；正常动效沿用既有 token。

## 范围与边界

覆盖 `SettingsAppearancePage` 的正文约束与 `_AppearanceTaskCard` 的重复容器。

不覆盖主题存储、`onChanged`、`onApply`、设置摘要入口、路由、文案、主题 token 或 `YhSegmented` 的公共 API。保留 48dp 触控目标、互斥语义和左右方向键。

## 自评审

1. **保留全高卡片**：否决。8 张当前候选显示，控件只占左上角，边框把大量无信息空间标记为设置内容。
2. **用三个独立按钮替代分段控件**：否决。会破坏互斥关系、箭头键连续选择和已建立的外观交互模式。
3. **保留单一分段选择线**：采用。视觉边界与任务本身一一对应，紧凑端更直接，宽屏不显稀疏。

## 核验清单

- 视口：360×800、768×900、1200×900、1600×1000；亮暗主题。
- 操作：点击三种主题、左右箭头、Tab/Shift+Tab、来源信息、应用主题与返回。
- 可访问性：互斥选中语义、48dp 命中范围、可见焦点、无横向滚动、无横向裁切、减少动态。
- 回归：选择即时生效，`onChanged` 与 `onApply` 回调不变，设置摘要仍仅提供详情入口。

## 实现界限

仅使用现有清源 token 与组件，不新增裸视觉值、Fluent/Material/Cupertino 成品控件或第二套主题状态。
