# 页面状态与关键流程

## 状态语法

每个远程或本地数据区域都使用同一套六态语法。页面可同时存在不同区域状态，不用一个全屏加载态遮住全部内容。

| 状态 | 保留内容 | 用户看到什么 | 可执行动作 |
|---|---|---|---|
| initial | 页面框架 | 尚未读取的原因 | 连接或首次读取 |
| loading | 有缓存则保留 | 区域进度与“正在更新” | 可取消时显示取消 |
| content | 最新或标明时间的缓存 | 内容、来源、更新时间 | 进入详情 / 刷新 |
| empty | 筛选和页面上下文 | 为什么为空 | 清除筛选 / 去配置 |
| stale | 最近一次成功内容 | 过期时间与原因 | 重试 |
| error | 可用缓存和输入 | 具体失败、影响范围 | 重试 / 前往设置 |

Skeleton 只用于首次加载且布局可预测的区域；刷新已有数据时使用局部 Progress 或 StatusPill，避免页面跳动。

页面若在进入时立即自动读取，可从首帧直接进入 `loading`，不为不可操作的瞬时阶段伪造可见 `initial`；`operation-locked` 等交互场景态在基础状态之外单独登记，不能取代实际可到达的六态。

## 交互验收优先级

截图完整不代表页面已经完成。每个真实任务流必须按以下顺序验收：

1. **操作协同**：重复触发必须单飞或明确拒绝；切换账户、筛选、页面或渠道后，旧请求不得回写；主行动、返回、取消和弹层不能绕过同一操作锁。
2. **恢复便捷性**：失败时保留仍有效的内容、输入和来源上下文；在原位置提供重试、取消或前往配置，不要求重启应用或重新走完整流程。
3. **未设计状态**：除标准六态外，逐页检查外部应用拒绝打开、权限变化、插件不可用、部分完成、并发操作、系统返回、任务取消、页面销毁和异常抛出。发现后先补参考与行为契约，再修改 Flutter。
4. **逐屏视觉评审**：以上状态均具备确定性参考后，逐张检查布局密度、滚动、断行、溢出、触控目标、焦点、亮暗对比和平台适配；不得用平台平均或抽样掩盖失败页面。

同一操作的按钮、忙碌文案、成功反馈与错误恢复使用一致动词。任何失败文案都不得声称未发生的副作用，例如没有成功交给系统浏览器时不得显示“已在浏览器中打开”。

## 首次启动与本地保护

```text
协议确认 → 设置本地解锁 → 可选连接校园账户 → 进入主页
                         ↘ 暂不连接 → 主页显示可操作的未配置状态
```

- 协议拒绝直接结束流程，不用弱化文案诱导同意。
- 解锁方式说明用途是保护本机数据，不声称替代学校账户安全。
- 跳过连接后仍可进入应用；需要远程数据的区域各自说明配置入口。

## 统一身份认证

```text
设置 / 业务未配置状态 → 输入账号凭据 → 系统认证 → 校验可复用登录态
                                      ├─ 成功 → 回到来源页面并刷新该域
                                      └─ 失败 → 保留输入上下文并说明修正方法
```

- 用户始终知道自己正在连接“统一身份认证”，界面不暴露 Cookie、适配器或解析器术语。
- 业务页发起认证时携带来源，成功后返回该页，不一律跳到设置首页。
- 超时、密码错误、校园网不可达使用不同错误文案。

## 查看详情

```text
列表/卡片 → 详情页 → 可选的二级详情或外部边界 → 原路返回
```

- 返回后恢复筛选、标签页、滚动位置和缓存内容。
- 详情加载失败只替换详情内容，原列表仍可返回。
- 原始来源、更新时间和只读边界在详情中可找到。

## 外部网站与 PDF

- 打开前显示目标名称；需要登录时说明将使用何种现有登录态。
- WebView 顶部始终提供返回、标题、在系统浏览器打开和刷新。
- WebView 主文档失败时不自动离开应用：以失败请求地址为当前地址，提供原地重试和显式外部打开；重定向失败的重试不得退回最初入口地址；系统浏览器拒绝或抛出异常时仍停留在当前页并允许重试。
- 工具栏返回与系统返回使用同一规则：网页存在历史时先后退网页，否则退出当前路由；外部打开进行中锁定重复触发。
- 外部打开结果绑定用户确认时的 URL 与文档代次；等待系统浏览器期间网页跳转或重试后，旧成功/失败不得覆盖新页面。
- 用户在外部打开失败后继续浏览到新地址时，清除旧地址的失败反馈，不把旧上下文带入新页面。
- 根路由无法退出时恢复网页历史拦截；下一次系统返回必须重新检查网页历史，不能沿用上一次临时放行。
- PDF 保留页码、缩放和下载/外部打开；加载失败显示文件来源与重试。
- 离开应用或系统浏览器不再受本地保护范围控制时，文案明确边界。

## 教务证据详情

- 第二课堂与体育考勤使用独立任务页；顶部始终保留返回、来源时间和原地刷新，不重复套主应用导航壳。
- 第二课堂按“完成度—积分证据—规则”分层；规则进入独立阅读页，详情页不重复堆叠完整规则矩阵。
- 体育考勤在宽屏保持可比较的汇总与记录，在紧凑视口改用完整字段记录卡，不依赖横向拖动才能看到地点、状态或原始记录。
- 刷新必须单飞。刷新失败时保留当前证据并显示原地反馈；成功后整体替换为同一代快照，退出页面后旧结果不得回写已销毁页面。

## 成绩、考试与过程化成绩

- 三页共享“筛选范围—来源—原始证据”阅读顺序，但不得合并学期模型：成绩详情只做前端字符串分组，考试与过程化成绩继续向 EAMS 传递真实 `semester.id`。
- 考试按连续时间轴排列，待公布日期、地点和临时说明必须与已排期记录同时可读；不能为了表格整齐而隐藏不完整记录。
- 成绩详情将 GPA、学分和课程数作为当前筛选范围的汇总，原始成绩文本保持原样；过程化成绩按课程聚合课堂表现、作业和测验证据，不与总评成绩重新计算。
- 刷新或搜索期间锁定重复请求和筛选切换，但保留当前范围、有效记录与返回路径。失败保留最后有效快照并在原位置重试；成功后才整体采用服务返回的学期与结果。
- 凭据、父页快照或页面生命周期换代后，旧请求不得回写；服务抛出异常也必须解除操作锁。筛选项在新快照中消失时回退到仍有效的范围，不保留不可执行的幽灵选择。

## 课程表

- 课程表是主目的地中的“每周学程地图”：桌面保留七天横向关系，紧凑端使用当天列表，并始终将今天滚动到可见位置。
- 首次读取、空数据与错误状态必须保留学期、校历入口和原地重试，不用通用 Banner 代替完整恢复路径。
- 有课表时刷新必须单飞并保持星期选择与当前课程可读；失败保留最后有效课表，成功整体替换同代快照。
- 凭据切换、外部快照换代或页面退出会使旧请求失效；旧结果不得恢复已清除的账户课表。

## 清除本地数据

```text
数据与隐私 → 查看清除项 → 确认 → 执行进度 → 完成并回到首次启动
```

- 确认页分别列出凭据、缓存、个性化设置和本地文件。
- 主按钮写“清除本地数据”，不使用含糊的“确定”。
- 任一步失败都列出已清除与未清除项目，不宣称全部成功。

## 无障碍与输入方式

- 读屏顺序遵循视觉阅读顺序；状态变化通过 live region 或 Flutter Semantics 通知。
- 所有可点击目标至少 48dp；鼠标 hover 不承载唯一信息。
- 键盘可到达主导航、页面操作、筛选、列表与详情；焦点进入弹层后被约束，关闭后回到触发器。
- 减少动态时取消位移和缩放，允许必要的瞬时状态切换。
