## 用户与单一任务

对象是在桌面端核对学校邮件的学生。单一任务是先从三封最近邮件中定位主题，再在同一屏阅读正文，而不是进入一个被空白占据的“阅读器框”。

## 视觉方向

页面保留清源的列表—详情双栏：左栏是紧凑的收件索引，右栏是按正文自然生长的阅读纸张。纸白 `neutral.surface`（`#FFFFFF`）、墨色 `neutral.fg`（`#1C1B1A`）、边界灰 `neutral.border`（`#D1CEC9`）、清源青 `brand.strong`（`#478384`）与青雾 `brand.tint`（`#E9F0F0`）继续来自 token 真源；不为短邮件制造补白、伪附件或装饰统计。

## 冻结编排

```text
1200+
┌ 收件索引 284 ┐  ┌──────── 阅读纸张 ────────┐
│ 选课结果确认  │  │ 教务处            今天 08:12│
│ 图书馆到期    │  │ 选课结果确认通知             │
│ 网络维护      │  │ 收件人 / 分隔线 / 正文         │
└──────────────┘  └──────────────────────────┘
       ↑ 都按各自内容高度结束，不互相拉伸

360 / 768
┌ 收件索引 ┐ → 点击后进入现有独立邮件详情页
```

- 宽屏左、右栏均移除固定最小高度；邮件列表按条目数收束，正文按实际正文长度收束。
- 宽屏仍使用现有的 284dp 列表宽度、列表选中态、键盘方向键、焦点处理和内联选择；不改变主从关系。
- 加载、未读取、空与错误仍使用各自的恢复面板；恢复面板收束至 `layout.formContentWidth` 并由内容决定高度，不把“没有可读邮件”伪装成短邮件阅读纸张或全宽空白卡。
- 移动端不变：只显示列表，进入独立详情页，避免在窄屏引入双栏或内部滚动。

## 动效与可达性

- 选中态、悬停与焦点继续使用清源基础控件的快速动效；减少动态时即时切换。
- 自然高度变化不额外制造页面跳动：列表与正文均从顶部对齐，切换短/长邮件只改变正文下边界。
- 邮件正文继续由 `YhSelectableText` 呈现，保持复制、语义名称和正文读取顺序。

## 不在本批范围

不改变 IMAP/POP/SMTP 服务、缓存、自动刷新、邮件内容、撰写流程、路由、邮件列表条目高度或任何网络请求。
