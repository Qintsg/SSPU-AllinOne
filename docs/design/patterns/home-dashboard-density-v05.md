## 目标

首页显示设置允许用户关闭培养方案、校园卡、邮箱和体育考勤。旧布局无论剩余多少项目，都用等高网格填满右侧区域，导致单项或空状态出现大片无信息留白。本稿只调整布局预算，不增加业务数据或新的设置项。

## 参考编排

```text
expanded / large
+---------------------------+----------------------+
| 今日学程时间轨            | 1-2 项：内容高度账本  |
|                           | 3-4 项：等高账本      |
+---------------------------+----------------------+

+--------------------------------------------------+

compact
+----------------------------------------------+
| 今日学程时间轨                              |
+----------------------------------------------+
| 1 项：单行概览 | 2 项：一行双列 | 3-4 项：两行 |
+----------------------------------------------+
```

## 布局契约

- 0 项可见概览：不渲染概览外框；主时间轨在中大屏占满主区宽度，紧凑端保留基准时间轨高度但不预留概览行。
- 无概览的紧凑端使用内容流布局，让行动坞紧跟时间轨，剩余空间只出现在页面底部，不夹在两个可操作区域之间。
- 1–2 项可见概览：桌面端使用内容高度（每项至少 `control.regular + spacing.s`），不把单项拉伸到时间轨高度；紧凑端按实际行数计算高度。
- 3–4 项可见概览：保留共享面板和分隔线，行高等分主区，避免每个摘要重复套卡。
- 设置切换后布局使用 `motion.base`（当前 200ms）完成尺寸过渡；系统启用“减少动态”时立即切换。
- 所有摘要仍为只读语义；可点击的校园卡继续保留 48dp 命中区和详情入口。
- 360×800 默认文字缩放不得出现页面滚动；文字放大超过 1.2 倍时允许滚动但不能裁字。

## 自评审

### 方案比较

1. **增加占位卡或装饰内容**：否决。会掩盖用户关闭项目后的真实状态，并增加认知负担。
2. **继续等高填充所有项目**：否决。正是当前大面积空白的来源，尤其在只保留一个项目时最明显。
3. **按可见数量收束并保留共享账本**：采用。既减少无效留白，又不改变用户熟悉的项目顺序、颜色和操作入口。

### 核验清单

- 视口：360×800、768×900、1200×900、1600×1000。
- 主题：亮色、暗色。
- 可见数量：0、1、2、3、4。
- 操作：设置切换、校园卡进入详情、键盘 Tab/Shift+Tab、触控命中区、减少动态。
- 失败状态：概览数据失败时仍显示恢复说明，不因为收束布局而丢失重试或上下文。

## 实现边界

只修改首页展示层和对应视觉/行为测试，不改变 service、model、缓存、认证或首页设置的存储语义。参考稿确认后，Flutter 实现不得添加新的业务请求。
