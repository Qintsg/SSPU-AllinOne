# 任务型模态框

## 目标

本地密码与微信公众号高级配置都是短暂打断当前设置任务的模态流程。它们必须保持原页面上下文可见，同时在 360×800 到 1600×1000 的窗口中完整容纳标题、说明、字段、原位错误和行动区。

## 视觉方向

- 色彩继续使用清源墨蓝、青雾、纸白、错误红与遮罩 token，不增加模态专属配色。
- 标题、正文与技术字段均使用 MiSans；技术键只作为辅助说明，不与主标签争夺层级。
- 密码对话框封顶为紧凑任务宽度；微信公众号配置在 768 起采用双列。紧凑端的四个认证字段保持单列，最后两个短数值字段组成一行“请求限制”，避免在一个语义组中间形成滚动断点。
- 对话框与视口四边至少保留 `space-m` 安全边距，内容溢出时只滚动正文，标题与行动不被推出视口。
- 行动区保持右对齐的小按钮组；空间不足时自然换行，不扩展为无必要的整行大按钮。
- 唯一视觉签名是标题上方的任务 eyebrow：“本机安全”或“高级认证配置”，帮助用户确认操作边界。

## 状态与协同

| surface | content | validation-error |
| --- | --- | --- |
| `security.password-dialog` | 两个密码字段、取消、设置密码 | 保留输入，原位说明两次密码不一致 |
| `settings.wechat-config` | 四个认证字段 + 一行请求限制、取消、保存 | 保留全部字段，只在无效数值字段显示范围 |

- 模态打开后焦点进入首个可编辑字段；Tab 顺序为字段 → 取消 → 主行动。
- 校验失败不关闭模态、不清空敏感字段，也不在页面背后显示重复 Toast。
- Escape 与取消返回原设置页；危险的移除密码流程继续禁止点击遮罩误关闭。
- 进入、退出使用 `motion.base`；减少动态时直接切换。

## 自评审与冻结条件

本稿没有增加新的卡片层级，也没有把技术配置包装成六张独立卡片。密码模态保持单一安全任务；高级配置在宽屏使用两列，在紧凑端只将两个同属请求限制的短数值字段同行，四个认证字段仍保持单列阅读。所有输入继续维持 48dp 最小触控高度。行动按钮维持最小触控目标但不强制等宽，避免再次出现过大的按钮框。

只有四档视口、亮暗主题、键盘焦点、错误保留、无横向溢出与安全边距全部通过后，本稿才可进入 Flutter 实现。
